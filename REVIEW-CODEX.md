# Implementation review

Reviewed the implementation at the current checkout, including Terraform, Packer/provisioners, node startup, custom build/tests, Cloud Build, all workflows, shell helpers, C# application/tests, bootstrap and operational documentation. Plans were not used as evidence of implemented controls. No cloud resources were created. Shell syntax checks passed (`bash -n`); .NET, Terraform, Packer and PowerShell are unavailable locally, so this is a source review, not a successful deployment or test run. Findings below describe independent defects; earlier failures can mask later ones.

## Blocker

1. **Test and production share state and can destroy each other.** `infra/versions.tf:5`, `.github/workflows/pipeline.yml:250`, `.github/workflows/promote.yml:88`. Both initialize the same repository-variable bucket and `winbuild` prefix, use the default workspace, and manage the same resource addresses/network names. A test apply can replace production, followed by test destroy deleting it. Ref-specific pipeline concurrency and separate promotion concurrency do not prevent interleaved applies/destroys. Contrary to `docs/adr/0006-adopt-terraform-and-packer.md:15`, no environment workspaces exist. **Fix:** isolate state, names and credentials per environment; isolate each ephemeral run or serialize its entire lifecycle. Make destroy select the exact run state explicitly.

2. **The image build depends on a network that is created only after the build.** `packer/windows.pkr.hcl:111`, `infra/main.tf:12`, `.github/workflows/pipeline.yml:235`. Packer requires `wb-net`/`wb-subnet`; bootstrap creates neither, and Terraform runs after image building. A clean project cannot build its first image; successful teardown removes these resources again. **Fix:** provision a persistent builder network before invoking Packer, separately from ephemeral application infrastructure.

3. **SSH key written to Windows is malformed.** `packer/windows.pkr.hcl:144`, `cloudbuild/image.yaml:77`. Metadata is `packer:ssh-ed25519 BASE64`, but splitting whitespace and taking elements 1..2 discards `ssh-ed25519`. The authorized-keys file contains no valid algorithm/key pair, so SSH authentication fails. **Fix:** remove the username prefix at the first colon and preserve the complete remaining OpenSSH public key; validate it before restarting sshd.

4. **IAP management has neither the VPC firewall nor IAM access it needs.** `infra/main.tf:25`, `bootstrap/00-bootstrap.sh:77`, `packer/windows.pkr.hcl:119`. No active provisioning path creates an IAP ingress rule for TCP 22 on `wb-builder`, or grants the controller `roles/iap.tunnelResourceAccessor`. Guest Windows firewall rules do not open the VPC firewall. The unused shell network helper only allows RDP on `wb-node`. **Fix:** create scoped builder SSH and debug RDP VPC rules and grant tunnel access to the actual controller/operator principals.

5. **Regional Application LB is missing its proxy subnet and traffic allowance.** `infra/main.tf:17`, `infra/main.tf:25`, `infra/main.tf:157`. `EXTERNAL_MANAGED` regional proxies require an active `REGIONAL_MANAGED_PROXY` subnet. Backends receive application connections from that subnet, whereas the firewall admits only health-check/global proxy ranges. Creation fails without the proxy subnet; adding it alone still leaves requests blocked. **Fix:** provision the regional proxy-only subnet, associate the forwarding rule with the intended network/subnet as required, and allow its CIDR to backend TCP 80 while retaining health-check ingress. See [Google's LB overview](https://docs.cloud.google.com/load-balancing/docs/https) and [firewall requirements](https://docs.cloud.google.com/load-balancing/docs/firewall-rules).

6. **Private nodes cannot fetch their package or monitoring dependencies.** `infra/main.tf:17`, `infra/main.tf:54`, `image/node-startup.ps1:119`. Nodes have no external IP, Cloud NAT or subnet Private Google Access. Thus GCS/Secret Manager access is not provisioned, and a real Dynatrace install also needs internet egress. **Fix:** enable Private Google Access for Google APIs and provide controlled NAT/proxy egress for external services, or stage all required installers privately.

7. **Node boot disks are smaller than the source image disk.** `packer/windows.pkr.hcl:100`, `infra/main.tf:48`. Packer captures a 60 GB boot disk, but the instance template requests 50 GB. Compute cannot create a boot disk smaller than the source image's disk size. **Fix:** request at least the image disk size (or build a smaller image); validate this relationship before deployment.

8. **Published NuGet package contains no deployable `payload/`.** `src/WinBuild.SampleApp/WinBuild.SampleApp.csproj:30`, `.github/workflows/pipeline.yml:117`, `image/node-startup.ps1:132`. A comment promises published output, but there is no publish target, package mapping or `PackagePath="payload"`. Ordinary `dotnet pack` packages build/library output, not a complete IIS publish directory. Every node throws `package has no payload directory`; runtime dependencies/configuration would also be absent. **Fix:** publish first and explicitly package the entire publish directory under one known payload path; inspect that contract before pushing the package.

9. **Windows PowerShell cannot expand the `.nupkg` path used here.** `image/node-startup.ps1:111`, `image/node-startup.ps1:131`. The Windows PowerShell Archive module enforces the `.zip` extension even for ZIP-format NuGet bytes. Startup fails before payload discovery. **Fix:** copy/rename the verified archive to `.zip`, or use `System.IO.Compression.ZipFile` to extract it. See [Expand-Archive](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.archive/Expand-Archive).

10. **IIS scripts call a nonexistent WebAdministration cmdlet.** `custom/scripts/30-configure-iis.ps1:15`, `packer/scripts/smoke-test.ps1:14`, `custom/tests/20-iis-config.Tests.ps1:36`. `Get-WebAppPool` is not supplied by the imported WebAdministration module. Under Stop error handling this prevents the shipped custom build from configuring IIS. **Fix:** use `Test-Path IIS:\AppPools\...` / `Get-Item` (and `Get-WebAppPoolState` for state), consistently in scripts and tests.

11. **Assertion helper contaminates HTTP return values with log strings.** `custom/tests/Assert.ps1:45`, `custom/tests/10-app-contract.Tests.ps1:19`. `Write-Assertion` uses `Write-Output`; `Assert-HttpOk` consequently returns both a PASS string and a response. Assigned results become arrays, and `$health.Headers.Contains(...)` no longer operates on the response header collection. Failure paths also return a truthy FAIL string rather than only null, causing secondary exceptions. **Fix:** write diagnostics to the information/host stream and return exactly one response object or null; exercise the helper in both Windows PowerShell and pwsh.

## Major

12. **WIF permits unreviewed branches/PR code to use the privileged deployer.** `bootstrap/00-bootstrap.sh:113`, `bootstrap/00-bootstrap.sh:120`, `.github/workflows/pr-checks.yml:127`. The trust condition restricts repository only; the claimed main-only restriction is absent. A same-repository PR receives deployer credentials while executing PR-controlled Terraform, which can run external programs. This identity can manage compute, secrets and all storage before production environment approval. **Fix:** bind immutable repository/owner IDs, trusted refs and workflow/environment claims; run PR plans with a separate read-only identity and keep production credentials inaccessible to PR/test workflows.

13. **VM identities can read or modify Terraform state and unrelated artifacts.** `bootstrap/00-bootstrap.sh:81`, `bootstrap/00-bootstrap.sh:93`, `bootstrap/00-bootstrap.sh:96`. All bindings are project-wide: the builder's objectAdmin covers the state bucket and all artifacts, and a compromised public-serving node can read every bucket's objects, including state. The deployer additionally gets secretmanager.admin and serviceAccountUser on every service account, enabling broad secret access and impersonation through VMs. This contradicts `docs/THREAT-MODEL.md:10` (one bucket). **Fix:** use bucket/secret/service-account resource bindings, give the builder only required input/output access, and split deployment identities by environment.

14. **Cloud Build does not use the service account bootstrap configures.** `bootstrap/00-bootstrap.sh:87`, `cloudbuild/image.yaml:18`, `.github/workflows/pipeline.yml:71`. The dedicated `sa-winbuild-cloudbuild` is never selected by the YAML or submit command. Builds run under the project's default build identity, whose permissions are neither configured nor predictable. The configured dedicated identity also lacks the debug secret creation/version permissions used at `cloudbuild/image.yaml:44`. **Fix:** select the dedicated controller SA explicitly and grant its exact image, instance, logging, bucket, IAP and optional debug-secret permissions; permit the deployer to act as that SA only.

15. **Packer controller container does not provision `gcloud` for IAP.** `cloudbuild/image.yaml:54`, `packer/windows.pkr.hcl:119`. Packer's IAP implementation invokes the gcloud CLI, but the hashicorp/packer step neither installs it nor shares it from the preceding gcloud container. Separate build steps do not share installed executables. **Fix:** use a pinned controller image containing Packer, its plugin, gcloud and SSH tools; check their presence before provisioning. See [Packer Google Compute builder requirements](https://docs.hashicorp.com/packer/integrations/hashicorp/googlecompute/latest/components/builder/googlecompute).

16. **Packer PR validation still supplies the removed WinRM interface.** `.github/workflows/pr-checks.yml:78`. It passes undeclared `winrm_password` and omits required `ssh_private_key_file` and `ssh_public_key`, so validation fails independently of the build. **Fix:** generate a disposable validation keypair and pass all current required variables; validate from the same working directory as Cloud Build.

17. **IIS hosting installation can succeed without an installed ASP.NET Core module.** `packer/scripts/install-toolchain.ps1:55`. The hosting bundle is installed before IIS is enabled, its exit code is only logged, and download/install exceptions are downgraded to warnings with the incorrect claim that the SDK supplies IIS integration. Hosting installed before IIS requires repair after enabling IIS. **Fix:** enable IIS first, install/repair the hosting bundle, reject installer failures and verify AspNetCoreModuleV2 registration before starting the app.

18. **Default IIS site conflicts with the app's wildcard port-80 binding.** `custom/scripts/30-configure-iis.ps1:24`, `packer/scripts/smoke-test.ps1:17`. IIS feature installation creates Default Web Site on `*:80:`; the scripts never stop/remove/rebind it before creating WinBuildApp on the same binding. App startup can fail or localhost requests reach the default site. **Fix:** explicitly remove/rebind the default site and assert only the intended site owns the application binding.

19. **Pipeline verify and audit lack required project environment variables.** `.github/workflows/pipeline.yml:296`, `.github/workflows/pipeline.yml:392`, `scripts/lib/common.sh:9`. Both shell scripts source common.sh, which requires PROJECT_ID, but their jobs only provide RUN_ID/VERSION, not PROJECT_ID (nor the configured REGION). Auth/setup-gcloud does not export this custom variable. Even after adding it, `verify-through-lb.sh:40` queries `wb-<run>-bs`, while Terraform creates `<run>-bs`. **Fix:** explicitly map project/region and consume the actual backend name from Terraform outputs.

20. **Deploy verification runs before backend readiness.** `.github/workflows/pipeline.yml:288`, `.github/workflows/promote.yml:104`. Terraform apply completion is not proof of Windows startup/LB health. The custom suite sends immediate requests with no readiness retry, preceding the shell script's wait in test and with no wait in promotion. A valid deployment can fail transiently. **Fix:** wait for both expected backend instances to become HEALTHY before running contracts; use exact health-state equality, not common.sh's substring `grep -c HEALTHY`, which also matches UNHEALTHY.

21. **Partial Terraform applies skip destroy.** `.github/workflows/pipeline.yml:353`. Cleanup requires deploy result success. If apply creates VMs/LB resources and later fails, the destroy job is skipped even though state records surviving resources. README.md:13 and docs/COST.md:23 promise cleanup regardless of earlier failures. **Fix:** schedule cleanup after any attempted apply, use its isolated state and complete inputs, and preserve/report cleanup failures.

22. **Reaper deletes MIG instances, which the MIG recreates.** `scripts/reap-leftovers.sh:13`, `infra/main.tf:86`. The scheduled cleanup only deletes individual VMs; the manager still targets two nodes. Autohealing/MIG reconciliation recreates the nodes, and LB/address resources remain billed. **Fix:** expire the whole deployment via its state or delete/resize the owning MIG before dependent resources; reap disks, addresses, LBs and orphaned builder resources as well.

23. **Audit can falsely certify an empty project.** `scripts/assert-empty-project.sh:7`, `scripts/assert-empty-project.sh:12`. It ignores RUN_ID in its filter, does not inventory MIG managers/templates/firewalls, and filters unlabelled backend/health-check/proxy/map resources by labels they never receive. All API errors are suppressed as empty output. It can miss leaked resources or accuse persistent production nodes from another run. **Fix:** combine exact run labels with names/ownership for unlabelled resources, include managers and dependencies, and fail on list/auth/API errors.

24. **Cloud Build's failure sweep is actually an unconditional parallel step.** `cloudbuild/image.yaml:103`, `cloudbuild/image.yaml:119`. `waitFor: ["-"]` launches cleanup at build start, not on failure; it can delete another live build if matching labels exist. Meanwhile Packer sets only image_labels (`packer/windows.pkr.hcl:105`), not VM labels, so the sweep, debug discovery and reaper cannot find this builder. Inventory waits for success, not failure. **Fix:** label temporary VMs with owner/build/run/TTL, and use a controller/finally mechanism scoped to the exact build, respecting debug retention.

25. **Promotion updates the template but leaves existing nodes on the previous release.** `infra/main.tf:105`. OPPORTUNISTIC updates apply only when instances are otherwise recreated. A second promotion to the existing `prod` MIG can report successful apply while continuing to serve old nodes, contrary to rollback/promotion expectations. **Fix:** use a valid regional PROACTIVE rolling replacement policy with surge/unavailable budgets compatible with the number of zones, and wait for rollout completion.

26. **Release tags are passed verbatim as NuGet versions.** `.github/workflows/pipeline.yml:39`, `.github/workflows/pipeline.yml:117`. `v1.4.0` becomes `Version=v1.4.0`; the leading v is not a valid NuGet semantic version. **Fix:** strip and validate the release tag prefix once, then use the normalized package version consistently in builds, manifests and endpoint assertions.

27. **Release attachment lacks write permission and is published before verification.** `.github/workflows/pipeline.yml:28`, `.github/workflows/pipeline.yml:155`, `.github/workflows/pipeline.yml:193`. action-gh-release needs contents:write, but receives contents:read. Further, manifest creation depends only on build/publish, so granting permission alone would expose a promotable release even if deploy/verify fails. **Fix:** grant contents:write only to a release-finalization job and gate that job on successful verification; verify release provenance during promotion.

28. **Exact version checks disagree with SDK informational versions.** `src/WinBuild.SampleApp/Program.cs:22`, `custom/tests/10-app-contract.Tests.ps1:28`. SDK builds in Git checkouts can append SourceRevisionId to AssemblyInformationalVersion, but assertions expect raw APP_VERSION. The shell check instead accepts any substring (`scripts/verify-through-lb.sh:29`), permitting a different version to pass. **Fix:** define a stable package-version response (or explicitly disable the source revision suffix) and expose commit separately; compare complete values on every backend.

29. **Monitoring inputs are accepted but discarded.** `infra/variables.tf:79`, `infra/variables.tf:85`, `infra/main.tf:65`. Neither dynatrace-dry-run nor otel-endpoint is included in template metadata. Telemetry is silently disabled; a requested Dynatrace dry run becomes a real installation when tenant/secret are configured. The default no-tenant test does not exercise Secret Manager, contrary to README.md:54 and docs/RUNBOOK.md:146. **Fix:** map both variables into metadata with stable boolean formatting, and assert metadata/export configuration explicitly.

30. **Deployed web.config is not the custom IIS configuration.** `custom/scripts/30-configure-iis.ps1:32`, `.github/workflows/pipeline.yml:117`, `image/node-startup.ps1:155`. Custom configuration is written only into the builder's publish directory. The independent Linux packing path never includes that file. Even after adding a standard publish payload, its generated web.config lacks the OTEL placeholders and custom environment/header settings; Replace silently does nothing. **Fix:** package one canonical configured publish output, or apply the full required IIS configuration at startup and fail if expected XML elements are missing. Escape endpoint values through XML APIs rather than raw text substitution.

31. **Debug builds can publish reusable administrator credentials in the image.** `packer/windows.pkr.hcl:197`, `packer/windows.pkr.hcl:214`, `packer/scripts/create-debug-user.ps1:27`. Debug enables a non-expiring local administrator and RDP, then follows the ordinary capture/family publication path without deleting that account or restoring settings. Sysprep generalization does not constitute explicit removal of custom users. Debug provisioning also happens after custom steps, so failures in those steps leave no promised RDP account. **Fix:** establish debug access before fallible steps, never publish a debug VM as a production-family image, and scrub users, key files and provisioning credentials before normal capture.

32. **Skip-image and documented rollback cannot select an older artifact.** `.github/workflows/pipeline.yml:80`, `docs/ROLLBACK.md:7`. skip_image_build still resolves the current run's generated image name, not the newest family image or an explicitly pinned previous image; that image normally does not exist. No input selects an old package/version. The documented command therefore neither reuses the advertised image nor rolls back. **Fix:** accept a validated immutable release manifest/image/package selection; document promotion of a previous successful release as rollback and ensure rolling replacement occurs.

## Minor

33. **Bootstrap emits bucket URLs where workflows expect bare names, and omits required outputs.** `bootstrap/00-bootstrap.sh:165`, `.github/workflows/pipeline.yml:64`. Printed STATE_BUCKET/ARTIFACT_BUCKET/BUILD_BUCKET include `gs://`; workflows prepend another `gs://` and Terraform's GCS backend expects a bucket name. GCP_ZONE and BUILDER_SA are required downstream but not printed. The immediate bootstrap verify job also reads repository variables before the user can configure them. **Fix:** output bare bucket names and all required variables, pass bootstrap outputs to its verify job directly, and document a separate verification dispatch if needed.

34. **Artifact lifecycle never expires current run objects.** `bootstrap/00-bootstrap.sh:57`. Every unique source/package path stays live, while the delete rule targets only noncurrent versions. Storage grows indefinitely despite the advertised 14-day lifecycle. **Fix:** define live-object retention for ephemeral prefixes and a separate retention policy for production/release artifacts that replacement nodes must still download.

35. **Toolchain version and validation claims exceed implementation.** `packer/scripts/install-toolchain.ps1:31`, `packer/scripts/install-toolchain.ps1:49`, `packer/scripts/install-toolchain.ps1:102`. BUILDTOOLS_VERSION only affects logging/image description; downloads use latest VS, a floating SDK channel, latest NuGet/gcloud and unsigned/unhashed fetched executables. Check() ignores native nonzero exit codes. docs/THREAT-MODEL.md:9 claims pinned versions. **Fix:** pin actual release manifests/versions and verify hashes or Authenticode signatures; check native exit codes and report actual installed versions in provenance.

36. **Public production endpoint has no TLS.** `infra/main.tf:157`, `infra/main.tf:178`, `.github/workflows/promote.yml:107`. Promotion reuses the HTTP-only public frontend with no HTTPS proxy/certificate. Production requests and diagnostic responses travel in plaintext. **Fix:** provision HTTPS with managed certificates and redirect HTTP; run verification against HTTPS.

37. **Public checkout accepts unbounded work and overflow values.** `src/WinBuild.SampleApp/Program.cs:108`, `src/WinBuild.SampleApp/Program.cs:118`. Unauthenticated callers control the task delay; multiplication can overflow to invalid negative milliseconds (500) or -1 (infinite wait), and request cancellation is not passed to Delay. This permits abandoned long-lived requests and incorrect negative orders. **Fix:** bound items to a small positive range, use checked arithmetic and pass RequestAborted to cancellable operations.

38. **The distribution test counts failures as node identities.** `custom/tests/10-app-contract.Tests.ps1:74`. A successful node plus an `error` string yields two distinct values and can satisfy the two-node assertion. Neither this test nor the shell script verifies the package version individually on every observed node. **Fix:** require successful responses with nonempty identity headers, compare against expected MIG instances, and verify version per identity; treat any request failure explicitly.

39. **Monitoring checks prove configuration/health, not telemetry delivery or agent grouping.** `custom/tests/30-dynatrace.Tests.ps1:24`, `image/node-startup.ps1:89`, `src/WinBuild.SampleApp/Program.cs:95`. The deploy test only checks healthz; startup accepts any running Dynatrace service and does not assert the requested host group. The status file subsequently overwrites the agent result with selfcheck/done. /telemetry enabled reports an exporter configuration, not successful export, and EXPECT_OTEL is never wired into workflows. **Fix:** verify the exact installed agent service/group and persist monitoring evidence separately; add an explicit collector/backend ingestion check before claiming delivery. Correct docs/RUNBOOK.md:188 and the test file's stronger assertions.

40. **Dependency/action execution is not immutably pinned.** `.github/workflows/pr-checks.yml:48`, `.github/workflows/pr-checks.yml:72`, `.github/workflows/pipeline.yml:123`. Security gates execute mutable master/main and version tags, with several jobs holding cloud/package credentials. **Fix:** pin third-party actions and controller images to reviewed commit SHAs/digests, automate reviewed updates, and narrow permissions to the individual jobs that need them.

41. **Custom step failure/timeout guarantees are incomplete.** `custom/run.ps1:89`, `custom/run.ps1:95`, `custom/README.md:23`. A fresh powershell.exe does not inherit the parent's Stop preference; arbitrary configured commands can emit nonterminating errors or ignore an earlier native failure and finish successfully. Kill() terminates only the shell, not spawned compilers/installers. **Fix:** wrap steps with explicit error/exit handling, document native exit-code responsibility, and use a Windows job object/process-tree termination on timeout.

42. **Legacy shell provisioning helpers cannot implement the advertised topology.** `scripts/lib/common.sh:81`, `scripts/lib/common.sh:98`. ensure_lb creates one zonal unmanaged group, attempts to add both zones' nodes to it, then addresses that zonal group with --instance-group-region. Nodes cannot belong to a different zone's group. It also lacks a named HTTP port and regional proxy network requirements. **Fix:** remove unsupported unused provisioning functions or maintain a tested topology with one group per zone and the correct backend flags.

43. **Cost guardrails are reported as installed when they are only suggestions.** `bootstrap/00-bootstrap.sh:141`, `bootstrap/00-bootstrap.sh:160`, `docs/THREAT-MODEL.md:12`. Bootstrap prints a quota instruction rather than enforcing 16 CPUs, and budget creation failures still return success. Unique image versions are retained without automated expiration, so steady image storage grows per run rather than remaining one image as docs/COST.md:24 implies. **Fix:** implement/verify quota and budget configuration, fail or explicitly report incomplete bootstrap, and define an image retention policy that protects deployed releases.

## Nit

44. **Operational docs retain incompatible management instructions.** `README.md:26`, `docs/RUNBOOK.md:27`, `docs/adr/0007-ssh-not-winrm.md:31`. README/runbook describe WinRM while the implementation uses SSH. ADR says no account needs revocation, but authorized key files/server configuration are captured without an explicit cleanup step. **Fix:** update the operational instructions to match SSH, document which access artifacts survive capture, and link troubleshooting to working IAP/network prerequisites. Mark superseded ADR-0005 as superseded in its own status header.
